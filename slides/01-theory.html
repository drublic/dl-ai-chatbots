Theory · Streaming

Why Chat UIs Stream

Streaming means the model sends tokens as they are generated — over the wire, piece by piece — instead of waiting for the full answer, then dumping it at once.

Perceived speed: first tokens beat a long spinner
Interruptible: user can stop mid-reply
Progressive UI: text, then tool status, then sources
Server streams · client hooks (useChat) update the list

Theory · Error recognition

States You Must Make Visible

State What the user should see
ready Input enabled · can send
submitted / streaming In-progress · disable send · optional Stop
error Generic “something went wrong” · retry possible
Tool running “Classifying… querying DB…”: not a frozen blank screen
Don’t leak raw API errors or keys. Recognize the class of failure; keep the UI honest.

Theory · Done means verified

Golden Questions + Refusal

Before we build: how you’ll prove the bot works — same language as the goals and OpenSpec.

Golden

Known-good season asks

Fixed questions with expected answers from the seeded DB (e.g. Merken Amateure → 6 riders). You run them in /chat.

Refusal

Off-domain stays off

Stock tickers, weather, unrelated trivia: classify → refuse — no fake SQL, no invented riders.

Step 5 is not “try random chats.” It is: goldens pass + one refusal you can demo.
